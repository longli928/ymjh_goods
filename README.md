# 一梦江湖礼包码批量兑换

一个纯静态的网页小工具：一次性给**多个大区、多个角色**批量兑换礼包码，并把成功/失败结果整理出来。

无需安装、无需后端、无需登录，浏览器打开就能用。

## 功能

- **一键导入角色**：粘贴 `大区名,角色ID1 角色ID2;大区名2,角色ID3;` 这样的文本批量填入，最多 20 个大区、每个大区最多 20 个角色
- **手动添加**：逐行添加大区，大区名支持联想选择
- **自动匹配大区**：根据大区名字自动查出对应的大区ID（用户界面上不显示），失败会提示
- **批量查询角色名**：一次查出所有角色的角色名，「角色名（角色ID）」的形式展示
- **批量兑换**：大区 × 角色 × 兑换码逐个兑换（串行发送，间隔 300ms），过程中可随时「停止」
- **结果展示**：汇总成功/失败条数、逐条结果表格；点击结果可展开查看接口**原始返回值**
- **失败名单**：列出失败的大区名 / 角色ID / 角色名，一键复制成 `大区名,角色id1,角色id2;大区名2,...` 格式，方便再次核对
- **公开兑换码清单**：页面底部默认折叠，内容来自 [goods/code.md](goods/code.md)，支持一键复制全部兑换码

## 原理

**整体架构**：全部逻辑都在浏览器里跑，没有服务端。

```
index.html   页面结构
css/style.css   全部样式（--glass 背景透明度、--blur 毛玻璃等变量集中在文件头部）
js/app.js       全部逻辑（接口请求、导入解析、兑换流程、结果渲染）
js/server-data.js   大区名 → 大区ID 对照表
goods/code.md   公开兑换码清单（页面底部折叠栏读取这个文件）
```

**调用的是游戏自己的两个接口**：

| 用途 | 接口 | 参数 |
| --- | --- | --- |
| 查角色名 | `https://com-sev.webapp.163.com/h42cdkey_role_check/api` | `role_id`（角色ID）、`hostnum`（大区ID） |
| 兑换 | `https://com-sev.webapp.163.com/h42cdkey_redeem/api` | `role_id`、`hostnum`、`code`（兑换码） |

**为什么用 JSONP 而不是 fetch**：这两个接口没有开放跨域（CORS）头，用 `fetch` 拿不到返回值。JSONP 通过动态插入 `<script>` 标签、由接口回调一个函数的方式取数据，不受跨域限制，所以整个工具能做成纯前端——**请求由访问者的浏览器直接发给游戏服务器，不经过本站服务器**，服务器只负责发静态文件。

**大区名怎么变成大区ID**：对照表写在 `js/server-data.js` 里（形如 `"踏月留香": "10003"`）。匹配规则是先精确匹配大区名，再尝试唯一模糊匹配，命中不了就在页面上红字提示。匹配到的 ID 存在隐藏字段里，只用来拼请求参数，界面上不展示。

**兑换流程**：先把「大区 × 角色 × 兑换码」展开成一个任务列表，然后逐个串行请求（每个之间等 300ms，单次请求 15 秒超时），避免并发过高被风控。角色名会按 `大区ID:角色ID` 缓存，兑换前若还没查过会自动补查一次。

**结果怎么判断**：接口返回 `status: true` 即兑换成功；否则按返回文案里的关键字归类（`兑换码不存在` / `已领取过` / `兑换码已过期`），都不命中就把接口原始 `msg` 原样显示。点开结果能看到完整的原始 JSON。

## 使用方法

1. **打开页面**：部署后用网址访问即可；本地也可以直接双击 `index.html` 看界面（`file://` 下样式和页面功能正常，但底部「收集的公开兑换码」读不到 `code.md`，且部分浏览器对本地页面的接口请求有限制，建议用 http(s) 环境）
2. **填角色**：把角色信息粘贴进「一键导入」框后点「一键导入信息」，格式为
   `大区名,角色ID1 角色ID2;大区名2,角色ID3;`
   （大区名和角色ID之间用**逗号**，同区多个角色ID用**空格**，不同大区之间用**分号**）
   也可以点「手动添加」逐行填写
3. **填兑换码**：一行一个
4. **点「批量兑换」**：会弹出确认框，点「已知晓并开始」后开始；也可以在兑换前先点「批量查询角色名」看看角色名对不对
5. **看结果**：结果表格、汇总、失败名单；失败名单可一键复制

**注意事项**

- 兑换期间**不要关闭/刷新页面、不要让设备休眠**，中途离开会有浏览器确认框拦截；进度和结果都只存在页面内存里，刷新即丢失
- 因为是串行请求，角色或兑换码多的时候会慢一些，属于正常现象
- 兑换结果以游戏服务器返回为准，本工具只负责把请求发出去并展示返回内容

## 部署

任意静态托管都可以（Nginx、GitHub Pages、Vercel、对象存储……），不需要 Node、数据库或任何后端服务。

## 维护

- **新增大区**：直接改 `js/server-data.js`，照格式加一行 `"大区名": "大区ID",` 即可。

## 贡献：提交新的兑换码

兑换码清单在 `goods/code.md`，是一个 Markdown 表格，欢迎通过 PR 补充。

**格式**

```
| 兑换码 | 添加时间 | 备注 |
| --- | --- | --- |
| ymjhvip520 | 2026.09.18 | 已过期 |
```

- **兑换码**：只填码本身，不要带空格、引号或其它符号
- **添加时间**：`YYYY.MM.DD`，填你确认它可用的时间
- **备注**：写清状态，例如 `已过期` / `2026落白活动`

示例改动：

```diff
  | 兑换码 | 添加时间 | 备注 |
  | --- | --- | --- |
  | ymjhvip520 | 2026.09.18 | 已过期 |
+ | ymjh2026 | 2026.09.20 | 有效期至 2026.10.01 |
```
